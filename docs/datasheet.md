# Datasheet — MMLU exam-QA (ДЗ 3)

## 1. Источник и лицензия

- **Источник**: [MMLU](https://huggingface.co/datasets/cais/mmlu) (Measuring
  Massive Multitask Language Understanding, Hendrycks et al., ICLR 2021) —
  тестовые вопросы с вариантами ответа по 57 предметам (от `abstract_algebra`
  до `world_religions`), охватывающим гуманитарные, социальные и точные науки.
- **Лицензия**: MIT (указана в карточке датасета на HuggingFace).
- **Локальное зеркало**: `../../datasets/mmlu/{test,validation}/0000.parquet`
  — скачано один раз через `huggingface.co/api/datasets/cais/mmlu/parquet/all/...`,
  дальше `dvc repro` работает офлайн, без обращений к сети.
- Готовый чужой набор — это сырьё, а не сдача (README, «Готовый датасет как
  источник»). `src/collect.py` делает с ним три вещи, каждая видна числом в
  `metrics/collect.json`:
  1. **Балансировка по темам** (`collect.max_per_topic = 200`) — без неё
     `professional_law` занимает 10.9% исходного `test`-сплита, выше порога
     `diversity.max_group_share = 0.10`. С кэпом крупнейшая группа — 2.2%
     (v1) / 3.5% (v2).
  2. **Переразметка в chat-формат** — исходная строка MMLU это table row
     (`question`, `choices[4]`, `answer`), не диалог. `collect.py` собирает
     пронумерованные варианты в один `user`-промпт и пишет в `assistant`
     букву и текст ВЕРНОГО варианта по полю `answer` источника.
  3. **Обогащение инструкцией** — в источнике инструкции нет вовсе (это QA,
     не chat); `collect.system_prompts` — 5 независимо написанных вариантов,
     выбираемых детерминированно по `sha1(id)`, чтобы модель не заучивала
     константную формулировку.

Разброс длины ответа `p90/p10 = 6.5` (порог гейта разнообразия — ≥ 1.6):
ответы — не фиксированная метка, а «буква + текст варианта», поэтому длина
естественно плавает с длиной самого выбранного варианта.

## 4. Как устроен сплит

- `split.group_key = "topic"`: сплит режет ЦЕЛЫМИ темами (см.
  `docs/defects.md`, дефект 3) — один и тот же предмет целиком уходит в
  train, val или test, никогда не разъезжается.
- Доли: train 0.8 / val 0.1 / test 0.1, `seed = 42`.
- Фактические доли из-за группировки отклоняются от целевых на десятые доли
  процента (v2: train 0.8119 / val 0.0980 / test 0.0902) — ожидаемо для
  сплита по группам разного размера, не баг.
- Контаминация проверена отдельной стадией (`src/contamination.py`,
  `scripts/check_contamination.py`) по четырём осям: id, нормализованный
  текст, группа, near-dup (Жаккар ≥ 0.85). На обеих версиях — **0**
  пересечений по всем четырём.

## 5. Известные ограничения

- **Язык** — контент на английском (MMLU — англоязычный бенчмарк), только
  системные инструкции написаны заново для этой работы.
- **Формат ответа искусственный** — «буква + текст варианта» получен
  переразметкой табличного QA в chat, это не естественный диалог, а учебный
  формат экзаменационного теста (как и оригинальный курсовой датасет НМО).
- **Источник размечен экспертами, но не без ошибок** — MMLU известен
  небольшим количеством вопросов со спорным или неточным правильным
  ответом (задокументировано в последующих работах, например Gema et al.,
  2024); `verify_answer_index`-подобной второй проверки разметки здесь нет,
  потому что у MMLU (в отличие от источника НМО) нет отдельного поля
  «правильный индекс по мнению другого размётчика» — `answer` и есть
  единственная разметка.
- **PII** — в академических тестовых вопросах персональных данных
  практически нет; на синтетической проверке (`check.sh`, тест 2) стадия
  корректно ловит телефон/почту/дату рождения (3 из 3 подложенных
  совпадений), но на реальном датасете `pii_hits` = 0 по всем трём типам —
  это ожидаемый, а не подозрительный результат для данного источника.
- **Тема не согласовывалась с преподавателем** — по договорённости с
  пользователем в этом прогоне ДЗ шаг явно пропущен.
